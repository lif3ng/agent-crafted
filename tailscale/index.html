Tier 1 — Daily Use
🟢 日常必会
每天都会用到的命令，掌握这两个 Section 就能处理 80% 的场景
1️⃣ 连接 & 状态 — 最常用的两个命令
# 连接到 Tailnet（日常最常用，开机后执行一次）
tailscale up

# 查看所有设备状态（谁在线、IP 是多少）
tailscale status
💡

status 输出解读：100.x.x.x 是 Tailscale IP。idle = 在线空闲，active = 正在通信，- = 离线。

2️⃣ Serve & Funnel — 暴露端口
直接 IPTailscale ServeTailscale Funnel
谁能访问Tailnet 内Tailnet 内整个互联网
HTTPS❌ 自己配✅ 自动✅ 自动

# 暴露 3 个本地端口到 Tailnet（注意前端端口要不同！）
tailscale serve --bg https / http://127.0.0.1:3000
tailscale serve --bg https:8443 / http://127.0.0.1:8080
tailscale serve --bg https:9999 / http://127.0.0.1:5173

# 确认规则
tailscale serve status

# 如需公网访问，再加 Funnel
tailscale funnel --bg https / http://127.0.0.1:3000
tailscale funnel --bg https:8443 / http://127.0.0.1:8080
📂 挂载点（Mount Point）— URL 路径路由
# 命令结构：tailscale serve https <挂载点> <后端地址>
tailscale serve --bg https /    http://127.0.0.1:3000   # / = 根路径，匹配所有
tailscale serve --bg https /api  http://127.0.0.1:8080   # /api 路径 → API 服务
tailscale serve --bg https /docs http://127.0.0.1:4000   # /docs 路径 → 文档服务
💡

访问 https://machine.ts.net/api/users → 转发到 127.0.0.1:8080/users（路径会去掉 /api 前缀）

🌐 后端不一定是本机 — 局域网地址也行
# 后端可以是任何本机能访问到的地址
tailscale serve --bg https / http://192.168.1.50:3000    # 局域网 NAS
tailscale serve --bg https / http://172.17.0.2:8080      # Docker 容器
tailscale funnel --bg https / http://192.168.1.88:8123  # Funnel + 局域网树莓派
💡

你的机器充当 HTTPS 网关：对外自动域名+证书，对内转发到任意可达地址（本机 / 局域网 / Docker）。唯一要求：运行 serve 的机器能访问到后端地址。

⚡ 易混淆：叠加 VS 覆盖

✅ 不同前端端口 → 叠加

tailscale serve --bg https / http://...3000
tailscale serve --bg https:8443 / http://...8080

→ 两条都生效 ✅

VS

❌ 相同前端端口 → 覆盖

tailscale serve --bg https / http://...3000
tailscale serve --bg https / http://...8080

→ 第二条覆盖第一条 ❌

🗑️ 关闭 & 清除
tailscale serve off https:8443    # 关某条
tailscale serve reset            # 全清
tailscale funnel off https       # 关 funnel

Tier 2 — Weekly Use
🔵 经常使用
每周会用到的功能，遇到对应场景时直接翻这里
3️⃣ Taildrop — 设备间传文件
# 发送文件（注意末尾冒号！）
tailscale file cp ~/report.pdf macbook:
tailscale file cp ./image.png server:

# 接收文件
tailscale file get .                # 接收到当前目录
tailscale file get ~/Downloads/     # 接收到指定目录
💡

设备名用 tailscale status 查看。macOS 接收的文件默认在 Downloads。

4️⃣ Tailscale SSH — 免密 SSH
# 在目标机器上开启（只需一次）
tailscale up --ssh

# 从任意设备直接连（无需密码/密钥）
tailscale ssh user@server-name
tailscale ssh user@100.x.x.x

✅ Tailscale SSH

  • 无需配公钥、无需密码
  • ACL 控制权限
  • 自动加密
VS

⚠️ 普通 SSH

  • 需手动配公钥
  • 需开放 22 端口
  • 需额外安全加固
5️⃣ MagicDNS — 用名字代替 IP
# 不用记 IP，直接用设备名
ping macbook
ssh user@server
curl http://nas:3000

# 完整域名
ping macbook.tailnet-name.ts.net
💡

MagicDNS 默认开启，自动为每台设备分配名字。用 tailscale status 查看所有设备名。

6️⃣ 网络排查 — 连不上时用
命令作用什么时候用
tailscale ping <device>测试连通 & 直连/中继连不上某设备时
tailscale netcheck检查网络质量、DERP 延迟延迟高/连不上时
tailscale whois <ip>查 IP 属于哪台设备排查访问来源
tailscale bugreport生成诊断日志提交 bug 时
 
# netcheck 关键输出：
UDP = true    # ✅ 可直连（快）
UDP = false   # ⚠️ 只能中继（通过 DERP 服务器）
Tier 3 — Advanced
🟣 进阶功能
需要时再查，知道有这些功能就行
7️⃣ Exit Node — 把别的节点当 VPN
# Step 1: 在出口机器上开启（只需一次）
tailscale up --advertise-exit-node

# Step 2: 在其他设备上使用
tailscale up --exit-node=server-name

# 关闭（恢复正常网络）
tailscale up --exit-node=
💡

所有流量都走 Exit Node。用 --exit-node-allow-lan-access 可保留局域网访问。ACL 必须允许。

8️⃣ Subnet Router — 暴露整个局域网
# 在局域网内的 Tailscale 机器上执行
tailscale up --advertise-routes=192.168.1.0/24

# 其他设备接收路由
tailscale up --accept-routes

✅ Subnet Router

暴露整个网段，访问未装 Tailscale 的设备

VS

🌐 Serve / Funnel

暴露本机端口，需本机跑着服务

9️⃣ 证书管理
# 获取 HTTPS 证书（用于自己的 Web 服务器）
tailscale cert server.tailnet-name.ts.net

# 生成：server.ts.net.crt + server.ts.net.key
💡

tailscale serve 已自动处理 HTTPS，不需要手动 cert。只有用自己的 Web 服务器时才用。

🛡️ ACL 访问控制
// 在管理后台 → Access Controls 编辑
{
  "acls": [{
    "action": "accept",
    "src": ["user@company.com"],
    "dst": ["tag:server:*", "tag:server:22"]
  }],
  "nodeAttrs": [{
    "target": ["tag:server"],
    "attr": ["funnel"]    // 允许 Funnel
  }]
}
Q&A
❓ 学习过程中的疑问 & 答疑
实际使用中遇到的真实问题，按场景分类
🔌 端口暴露相关
疑问答案
serve 多次执行，后面的会覆盖前面的吗？ 叠加 不同前端端口不会覆盖
覆盖 相同前端端口会替换
--bg 是什么意思？ background，后台运行。不加会阻塞终端，断 SSH 就停。建议始终加 --bg。
localhost 服务能用 Tailscale IP 直接访问吗？ 不能。服务绑定 127.0.0.1 时外部流量进不来。解法：① tailscale serve 代理 ② 改绑定为 0.0.0.0
Funnel 的 10000 端口有什么来历？ Tailscale 硬编码了 3 个 Funnel 允许端口：443（标准 HTTPS）、8443（HTTPS 备用）、10000（Webmin 默认端口）。前端端口只能从这三个选，但后端本地端口随便用什么。
serve 命令中间的 / 是什么意思？ 挂载点（Mount Point），即 URL 路径。/ = 根路径匹配所有请求；/api = 只匹配 /api 开头的请求。可以同时配多个挂载点分别转发到不同后端。
后端只能填 127.0.0.1 吗？ 不是。后端可以是任意本机能访问到的地址——局域网 IP（192.168.x.x）、Docker 容器（172.17.x.x）都可以。只要运行 serve 的机器能 curl 通目标地址就行。
🌐 网络原理相关
疑问答案
Serve 和 Funnel 到底什么区别？ Serve = 暴露给 Tailnet 内部设备（装了 Tailscale 的）
Funnel = 在 Serve 基础上再开放到公网（任何人都能访问）
Funnel 包含 Serve 的功能，但端口受限制（443/8443/10000）。
改绑定 0.0.0.0 和用 Serve 有什么区别？ 0.0.0.0 = 所有网卡都监听，局域网设备也能访问（不够安全）
tailscale serve = 只有 Tailscale 网络能访问，自动 HTTPS（更安全）
不想改代码就用 serve，想最省事就改绑定地址。
直连和中继有什么区别？ 直连（Direct）：设备间 WireGuard 打洞成功，点对点通信，延迟低速度快。
中继（Relay/DERP）：打洞失败，通过 Tailscale 中继服务器转发，延迟较高。
用 tailscale ping <device> 查看走的是哪种。
🛠️ 实操相关
疑问答案
Funnel 执行后报错怎么办？ ① ACL 没开 Funnel → 管理后台加 "attr": ["funnel"]
② 端口不在允许范围 → 只能用 443/8443/10000
③ Tailscale 版本太旧 → tailscale update 升级
怎么确认 serve/funnel 规则是否生效？ tailscale serve status — 查看所有 Serve 规则
tailscale funnel status — 查看所有 Funnel 规则
每次执行后养成跑 status 确认的习惯。
规则搞乱了怎么重来？ tailscale serve reset — 清除所有 Serve 规则
tailscale funnel reset — 清除所有 Funnel 规则
然后重新添加即可。

Pitfalls
💣 常见坑点
坑原因解法
相同端口覆盖前端端口相同时后执行覆盖前指定不同前端端口 https:8443
Funnel 端口限制公网只开放特定端口用 443 / 8443 / 10000
Funnel 需开 ACL默认不允许管理后台 ACL → nodeAttrs 允许 funnel
不加 --bg 断连前台运行，SSH 断了停养成加 --bg 习惯
防火墙拦截系统防火墙挡端口检查 ufw 或 macOS 防火墙
域名访问不了机器名含特殊字符tailscale status 查看正确名称
传文件没冒号file cp 必须加 :tailscale file cp file.pdf macbook:
